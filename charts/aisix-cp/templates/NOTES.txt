Access the dashboard via cp-api (reverse proxy):
  kubectl port-forward svc/{{ include "aisix-cp.fullname" . }}-api {{ .Values.api.service.port }}:{{ .Values.api.service.port }} -n {{ .Release.Namespace }}
{{- $base := trimSuffix "/" (lower .Values.api.publicBaseURL) }}
{{- if or (eq $base (printf "http://localhost:%v" .Values.api.service.port)) (eq $base (printf "http://127.0.0.1:%v" .Values.api.service.port)) }}
  Then open {{ .Values.api.publicBaseURL }}  (localhost and 127.0.0.1 both work)

  Sign-in is checked against the trusted origins: the api.publicBaseURL origin,
  its loopback twin — localhost and 127.0.0.1 are interchangeable — and anything
  in AISIX_TRUSTED_ORIGINS. Reaching the dashboard at some OTHER address (an
  Ingress, a LoadBalancer, a different port) is refused at sign-in with an
  "address not allowed" error. To allow one, either point api.publicBaseURL at it and
  upgrade the release, or add it to AISIX_TRUSTED_ORIGINS via ui.extraEnvVars —
  that one is additive, so use it when the console is reached through more than
  one hostname.
{{- else }}
  Then open {{ .Values.api.publicBaseURL }}

  Sign-in is checked against the trusted origins: the api.publicBaseURL origin,
  its loopback twin, and anything in AISIX_TRUSTED_ORIGINS. The port-forward
  above publishes the dashboard on http://localhost:{{ .Values.api.service.port }},
  which is not that origin — so unless you have already listed it in
  AISIX_TRUSTED_ORIGINS, the page loads and sign-in is refused. To allow it,
  add http://localhost:{{ .Values.api.service.port }} to AISIX_TRUSTED_ORIGINS
  via ui.extraEnvVars.
{{- if or (hasPrefix "http://localhost:" $base) (hasPrefix "http://127.0.0.1:" $base) }}
  Or forward the port api.publicBaseURL names instead — local port first,
  Service port second:

    kubectl port-forward svc/{{ include "aisix-cp.fullname" . }}-api <its-port>:{{ .Values.api.service.port }} -n {{ .Release.Namespace }}
{{- end }}
{{- end }}

Connect a data-plane (managed mode):
{{- if eq .Values.dpm.service.type "NodePort" }}
  DPM is exposed via NodePort.
  {{- if .Values.dpm.service.nodePort }}
  NodePort: {{ .Values.dpm.service.nodePort }}
  {{- else }}
  Get the assigned port:
    kubectl get svc/{{ include "aisix-cp.fullname" . }}-dpm -n {{ .Release.Namespace }} -o jsonpath='{.spec.ports[0].nodePort}'
  {{- end }}

  First set api.dpmgrBaseURL=https://<node-ip>:<node-port> and upgrade the
  release: dp-manager puts it in its server certificate, and without it the
  certificate covers only localhost, so the gateway rejects the connection.

  Then run the DP container (replace <node-ip> and <node-port>):

    docker run --rm \
      -e AISIX_CONFIG_PATH=/etc/aisix/config.managed.yaml \
      -e AISIX_MANAGED__CP_BASE_URL=https://<node-ip>:<node-port> \
      -e AISIX_MANAGED__CP_ETCD_ENDPOINT=<node-ip>:<node-port> \
      -e AISIX_MANAGED__CP_CERT_PEM='<client-cert-pem>' \
      -e AISIX_MANAGED__CP_KEY_PEM='<client-key-pem>' \
      -e AISIX_MANAGED__CP_CA_PEM='<ca-cert-pem>' \
      -v aisix-mtls:/var/lib/aisix \
      {{ .Values.api.dpImage | default (printf "docker.io/api7/aisix:%s" .Chart.AppVersion) }}
{{- else }}
  DPM is a ClusterIP service. Expose it via Ingress, LoadBalancer, or port-forward:
    kubectl port-forward svc/{{ include "aisix-cp.fullname" . }}-dpm {{ .Values.dpm.service.port }}:{{ .Values.dpm.service.port }} -n {{ .Release.Namespace }}

  Then set api.dpmgrBaseURL to the address you exposed and upgrade the
  release: it is both the address the console's install snippet hands out and
  the host dp-manager puts in its server certificate. Left empty it sets
  neither — the install snippet keeps its <your-dp-manager> placeholder, and
  the certificate is seeded with nothing but localhost.

  An IP address is the case that needs it. A gateway dialing a hostname
  offers that name in the TLS handshake and dp-manager issues a certificate
  covering it on the spot, so port-forward and a DNS-named Ingress or
  LoadBalancer each connect without this set. A gateway dialing an IP literal
  offers no name at all, so a LoadBalancer's external IP is covered only by
  naming it here — until it is, the handshake fails with nothing logged to
  say why.
{{- end }}
